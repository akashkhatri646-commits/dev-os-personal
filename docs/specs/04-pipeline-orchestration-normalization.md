# Spec 04 — Pipeline Orchestration, Job Queue and Normalization [MVP] (Component 1)

## 1. Goal
Run each record through the 8-stage pipeline asynchronously on Netlify with durable jobs, retries, idempotency and fail-closed behavior; implement the Normalization stage (type routing + OCR/parsing + quality floor).

## 2. Queue
Table `pipeline_jobs`, function `claim_jobs(limit, worker_id)` (see schema).
- One job per `(record_id, stage)` active at a time (unique partial index).
- Stage → next stage map: `consent_check → normalize → extract → map → validate → score → route → commit`. (`commit` job runs only for auto-commit decisions; human commits happen in the review submit handler.)
- `attempts` is incremented at claim time. `max_attempts` default `JOB_MAX_ATTEMPTS` (2) = "retry once".
- Backoff on failure: `run_at = now() + 15s * attempts`.
- Dead jobs: after `attempts >= max_attempts` → job `dead`, record → `needs_review` with `status_reason = 'stage_error:<stage>'` (or `llm_error` for upstream errors) and a review task is created (kind `escalation`) so no record is stranded. Exceptions: `consent_check` failing with `error` result → record `failed`; storage object missing → `failed`; admin alert via `ALERT_WEBHOOK_URL`.

## 3. Worker
- `POST /api/worker/tick` (header `X-Worker-Secret: $WORKER_SECRET`, constant-time compare; 401 otherwise). Not session-authenticated.
- Triggers: (a) Netlify Scheduled Function `netlify/functions/worker-schedule.ts` running `* * * * *` which `fetch`es the tick endpoint; (b) the ingestion handler and each stage completion also fire a best-effort `fetch` to tick (`fire-and-forget`, no await) to cut latency; (c) Supabase `pg_cron` optional fallback documented in spec 16.
- Tick algorithm: `claim_jobs(WORKER_BATCH_SIZE, workerId)` → for each job run `runStage(job)` with concurrency respecting `LLM_MAX_CONCURRENCY_PER_SOURCE` → stop when `WORKER_TICK_MAX_SECONDS` elapsed → respond `{claimed, succeeded, failed}`.
- `runStage(job)`:
  1. Load record (service role). If record status is terminal → mark job `done`, return.
  2. Verify expected status for the stage (idempotency): e.g. `extract` requires status `normalizing→extracting` transition not yet complete. If stage output already exists (e.g. extracted_fields rows) → skip work, advance.
  3. `setStatus(record, <stage-in-progress status>)`.
  4. Execute stage function (spec-owned): returns `{next: Stage | 'done' | {escalate: reason}}`.
  5. In one transaction: write stage artifacts (done by the stage), mark job `done`, enqueue next job, write audit event.
  6. Errors: classify `AppError.retryable`; retryable → job `queued` with backoff; else dead path.
- Each stage function is **pure with respect to the DB state**: it reads inputs from DB, writes outputs by upsert keyed on `(record_id, …)`, so re-running is safe.
- Budget guard before any LLM/OCR call: `budget.assert(orgId, estimatedUsd)` using daily sum of `ingestion_records.cost_usd` for org; over cap → delay jobs 10 min and alert (no failure).
- Cost accounting: each vendor call adds to `ingestion_records.cost_usd` via `increment_cost(record_id, usd)` helper (single `update … set cost_usd = cost_usd + $1`).
- Netlify limits: stage functions must finish < 60 s; a tick is a standard serverless function (26 s default / up to 60 s configured in `netlify.toml`; background function variant for the schedule). Therefore LLM calls use streaming off, `LLM_REQUEST_TIMEOUT_MS=60000` max, and the **extract** stage processes pages in page-group chunks, one chunk per job run (see spec 06 §6) to stay inside the limit. If sustained load exceeds this design, the same `runStage` is deployed as a long-running container worker (no code change; only the trigger differs).

## 4. Normalization stage (`stages/normalize.ts`)
Input: `documents` row + stored object. Output: `documents.normalized_text`, `page_count`, `ocr_confidence`, `ocr_engine`; page images for vision (stored at `{org}/{record}/pages/{n}.png`, ≤ 1600 px longest side, generated by `sharp`/`pdfjs`).

Routing (deterministic):
| `input_kind` | Processing |
|---|---|
| `hl7v2` | `hl7/parser.ts` (spec 03 §4); confidence 1.0 |
| `text` | single page text; confidence 1.0; blocks = paragraphs split on blank lines |
| `pdf` | If PDF has an embedded text layer with ≥ 200 chars/page average → extract text with `pdfjs-dist` (blocks from text items), `ocr_engine='pdf-text'`, confidence 0.99. Else rasterize pages (150–200 DPI) and OCR |
| `image` | Pre-process (deskew, grayscale/contrast via `sharp`), OCR |

OCR via `OcrClient` (`src/server/services/ocr/OcrClient.ts`):
```ts
interface OcrClient { recognize(pages: Buffer[]): Promise<OcrPage[]> }
interface OcrPage { page: number; text: string; confidence: number /*0..1 mean word conf*/;
  blocks: { id: string; text: string; confidence: number; bbox: [number,number,number,number] }[] }
```
Adapters: `textract.ts` (`DetectDocumentText` / `AnalyzeDocument` with TABLES when available) and `documentAi.ts`. Block ids are `p{page}b{index}`. bbox normalized to 0..1.

Quality floor:
- `ocr_confidence` = mean of page confidences weighted by character count.
- If `ocr_confidence < OCR_CONFIDENCE_FLOOR` (0.80) **or** any page confidence `< 0.60`: **do not extract**. Set record `needs_review`, `status_reason='low_ocr_quality'`, create review task (kind `escalation`, priority high) whose workspace shows the scan with banner "Low OCR quality — request a clearer copy or native digital file." Reviewer actions available: *Request re-upload* (marks `rejected` with `status_reason='reupload_requested'`) or *Proceed manually* is **not** offered in MVP. Audit `ocr.rejected_low_quality`.
- Else audit `ocr.completed` with `{engine, pages, confidence}`.
- Language: MVP supports English only. If the detected language (OCR response or `franc`) is not `en`, set record `needs_review` with `status_reason='language_unsupported'`, create an escalation task and skip extraction.
- Handwriting detection (Textract `HANDWRITING` flag / Document AI): if > 15% of blocks handwritten → force escalation with reason `handwriting`.

Compliance: OCR client may be called only after `consent_checks.result='valid'`; `normalize` asserts this (`assertConsentValid(recordId)` reads the row; throws non-retryable `CONSENT_REQUIRED` if absent).

### Implementation status (Feature 7, part 1)
Built: the `OcrClient` interface (it receives the original document bytes, mime type and page count rather than page images, since Textract and Document AI accept PDFs and images directly), HL7v2, text-note and PDF text-layer paths, the quality floor, language check, handwriting rule and the `ocr_unavailable` hold. Not yet built: the Textract / Document AI adapters and page rasterisation for the vision model. New reason codes: `ocr_unavailable` (retryable), `handwriting`, `document_missing`.

## 5. Real-time status
`ingestion_records` is in the `supabase_realtime` publication. Every `setStatus` updates `status`, `status_reason`, `updated_at` so the UI can render stage progress without extra tables. Stage durations come from audit events.

## 6. Edge cases
- Two workers claim same record's different stages? Impossible: next stage is enqueued only after the previous completes.
- Tick overlaps (schedule + fire-and-forget): `FOR UPDATE SKIP LOCKED` prevents double processing.
- Worker dies mid-job: `claim_jobs` re-queues `running` jobs locked > 5 min; stages are idempotent. Attempts still increment so repeated crashes escalate.
- Vendor returns partial pages: treat as retryable error; if still partial on retry → escalate `stage_error:normalize`.
- OCR returns empty text for a page: page confidence 0 → triggers floor rejection.
- Corrupt/encrypted PDF: non-retryable → `needs_review:unreadable_document`.
- Record deleted/moved status while a job runs: step 1 guard marks job done without side effects.
- Time budget: if tick budget is nearly exhausted, remaining claimed jobs are released (`status='queued'`, `attempts` decremented) instead of started.

## 7. Acceptance criteria
1. A record advances through all stages automatically with no manual call; each transition emits an audit event and a Realtime update.
2. Killing the worker mid-extraction results in the job re-running after 5 minutes without duplicate `extracted_fields` rows.
3. Two concurrent ticks never run the same job twice (integration test with 10 jobs/2 workers).
4. A job failing twice makes the record `needs_review` with a review task; nothing remains `running`/`queued` for it.
5. OCR confidence 0.78 → no LLM call is made (call-count assertion) and the record is escalated `low_ocr_quality`.
6. Digital PDFs with a text layer skip OCR; scanned PDFs invoke OCR exactly once per page.
7. Normalization is never invoked for a record without a `valid` consent check.
8. Tick endpoint rejects missing/incorrect secret with 401.
